# Agentsla

**Two-sided AI service escrow and validator-agreed settlement on GenLayer.**

Agentsla lets a requester escrow GEN under immutable natural-language terms,
name the provider, bind two authoritative sources, and give the requester a
fixed counter-evidence window. GenLayer validators authenticate every
hash-bound artifact and must agree on the categorical verdict before contract
logic can pay the provider or refund the requester.

## Steward-requested protections

| Concern | v3 behavior |
| --- | --- |
| Temporary outage or HTTP failure | `EVIDENCE_REVIEW`; escrow stays locked for retry |
| Hash mismatch or oversized artifact | `EVIDENCE_REVIEW`; it cannot become service failure |
| One-sided provider evidence | Requester has one hash-bound counter-evidence submission during a fixed challenge window |
| Unspecified truth source | Every SLA immutably commits two distinct public HTTPS authority URLs and SHA-256 hashes |
| Unagreed score | Scores are not collected, stored, displayed as canonical, or used for settlement |
| Validator disagreement | No categorical consensus means no settlement verdict |
| Repeated outages | The retry deadline is absolute and cannot be extended by retries |

`SATISFIED` can only pay the provider. `UNSATISFIED` can only refund the
requester. Timeouts and open-SLA cancellation are requester-only, and every
settlement path is single-use.

## Frontend write path

The browser app pins `genlayer-js` exactly to `1.1.8`. It calls
`walletClient.writeContract(...)`; that SDK method performs the supported
`estimateTransactionGas` flow before requesting the EIP-1193 wallet write. The
removed `estimateTransactionFeesForWrite` helper is not imported or called by
runtime code.
The app waits for `TransactionStatus.FINALIZED`, validates the actual simplified
receipt shape returned by v1.1.8, and then reads canonical latest-final state.
